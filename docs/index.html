Living PRD (Product Requirements Document)

Updated every week as we test with real users and learn what works.

1. Target User & The Job to Be Done

Who is this for? Comms firms that do news roundups for clients across multiple domains. E.g., when I worked at a PR agency, we would do a weekly newsletter for a B2B payments company, focused on news across FX, macroeconomics, fraud, etc..

The painful "Before" workflow: We manually search the web for the most relevant news in those categories from that week. We have access to subscriptions, but the company does not so if there's a paywall, they won't be able to read it.

The "After" workflow with this product: The tool scours the web for the relevant articles that week per category. It hyperlinks the direct link to the site and gives a 3 sentence summary of the article. For articles that require a subscription, a browser “add to newsletter” button lets the user capture articles they’re already logged in to read. The tool summarizes and links them without having to store login credentials.

2. Scope & Explicit Non-Goals

  • In Scope (Core Workflow): Automates newsletter creation based on industry categories and solves the paywall issue. It finds candidate articles per category from news feeds and search, then ranks them by relevance. It drafts a 3-sentence summary of each article. User reviews and edits the picks then is able to email the newsletter directly to client.
  • Out of Scope #1: Sending newsletters to clients automatically. The tool only produces a draft newsletter that a human approves and sends through the agency's email.
  • Out of Scope #2: Storing and using an agency's paid subscription credentials. The tool will use RSS feeds, news search APIs, and publicly available sites first.
  • Out of Scope #3: Attaching full article PDFs from paywalled sites.

3. How It Works Under the Hood & Riskiest Assumption (Week 2+)

Riskiest Assumption: The AI will pick and prioritize the articles and news sources that a PR professional would pick. It also risks the AI summarizing articles from public headlines and subheadlines if it can't bypass a paywall.

Simple Architecture: Client categories, keywords, priority sources→ App server pulls this week's articles from RSS feeds/a news API → LLM ranks relevance per category and drafts 3-sentence summary → User reviews and edits the output → User exports newsletter drafts and shares with client directly.
